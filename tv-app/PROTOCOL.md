# Office TV protocol (v1)

Office TV 3.0 does one thing: **whatever is on a laptop's screen shows on the office TV**, like a Chromecast.
A laptop, Chromebook or MacBook opens the website, enters the TV code, and shares its screen. The laptop
never needs the TV's IP address: both sides talk through a public pub/sub relay,
[ntfy.sh](https://ntfy.sh), and every message is end-to-end encrypted, so the relay only sees
random-looking text. The screen itself goes directly from the laptop's browser to the TV over WebRTC.

```
Website on the laptop (https://nikhildiwakar-bit.github.io/Portfolio/tv/)
        │  POST encrypted command            ▲  SSE: encrypted ack
        ▼                                    │
     https://ntfy.sh/<topic>  ───────────────┘       (also carries the WebRTC offer/answer, §8)
        │  streaming GET /json
        ▼
   Office TV app (on the TV)  ── runs ping / cast ──> posts encrypted ack
        │
        └─ CastActivity: full-screen receiver page  <══ WebRTC video + audio, peer to peer ══  laptop
```

Release builds of the app have **no** web server and accept nothing on the local network. (Debug builds,
used only by CI, have a loopback-only test API; see §9.)

Canonical test vectors: `tests/vectors.json` (generated by `tests/make-vectors.mjs`).
Both implementations **must** reproduce them exactly.

## 1. TV code

- 10 symbols from the Crockford base32 alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ` (50 bits).
- Generated once on the TV with `SecureRandom`, stored in prefs key `pair_code`. **New TV code** on the
  TV's home screen (with a confirmation) generates a new one; every laptop that saved the old code has
  to enter the new one.
- Displayed as two groups of five: `7K3M9-QX2TD`.
- **Normalisation** of user input (website side, and TV side when reading prefs):
  uppercase → remove spaces and dashes (`-`, U+2010–U+2015) → map `O`→`0`, `I`→`1`, `L`→`1` → must then
  be exactly 10 characters from the alphabet, otherwise invalid (`null`). `U` is invalid.

## 2. Derivation

All strings are UTF-8. `SHA256` is plain SHA-256.

| Value | Formula |
|---|---|
| topic | `"otv" + hex_lower(SHA256("officetv/topic/v1:" + code)[0..16))` → 35 chars |
| key | `SHA256("officetv/key/v1:" + code)` → 32-byte AES-256-GCM key |

## 3. Message envelope (ntfy message body)

```
otv1.<base64url(iv)>.<base64url(ciphertext || tag)>
```

- base64url **without padding** (RFC 4648 §5). Decoders must accept input with or without `=`.
- AES-256-GCM, 12-byte random IV, 128-bit tag, **AAD = UTF-8 bytes of the topic**.
- Plaintext is a UTF-8 JSON object (below). Any message that does not start with `otv1.`, or that
  fails to decrypt, is silently ignored. That is also how commands are authenticated: only someone
  who knows the TV code can produce a valid envelope.
- Keep the whole envelope under **3,900 bytes**. ntfy turns bigger messages into attachments.

## 4. Plaintext JSON

Website → TV (`dir: "c2t"`):

```json
{"v":1,"dir":"c2t","id":"k3j9x0a2m1","ts":1760000000000,"cmd":"cast","args":{"action":"start","session":"k3j9x0a2m1p4q8r2"}}
```

TV → website (`dir: "t2c"`):

```json
{"v":1,"dir":"t2c","id":"p0q8…","re":"k3j9x0a2m1","ts":1760000000950,
 "ok":true,"msg":"The TV is ready to show your screen.","data":{…},"part":0,"parts":1}
```

- `id`: 10+ random base36 chars, unique per message. `ts`: sender clock, milliseconds since epoch.
- Each side ignores messages with its own direction (both directions share one topic).
- **Freshness (TV side):** accept a `c2t` message only if `|ts/1000 − event.time| ≤ 300`, where
  `event.time` is the ntfy server's receive time in seconds (so the TV's own clock doesn't matter).
  If `event.time` is missing, compare with the TV clock. Commands the relay received more than 300 s ago
  (backlog after an outage) are dropped too, and so is any `id` seen in the last 256 messages. The
  laptop's clock must be roughly right; laptops sync automatically.
- The website matches acks by `re` against the commands it sent and ignores everything else.
- An ack is always a single envelope (`part` 0 of `parts` 1). If a result would not fit, the TV drops
  `data` and shortens `msg` (older apps split long app lists over several parts; 3.0 has none).

## 5. Commands

Every command gets exactly one ack with `ok` and a human `msg` in plain English that the website can show
as is. Office TV 3.0 has two commands:

| `cmd` | `args` | ack |
|---|---|---|
| `ping` | `{}` | `ok:true`, `msg` "The TV is online.", `data` = status object |
| `cast` | `{action:"start"\|"stop", session}` (session: 12–32 chars `[a-z0-9]`) | see §8; `start` acks carry the status object in `data` |

**Every other command** (including `open`, `youtube`, `key`, `volume`, `apps`, `app`, `file`, `screen`,
`awake` and `rename` from Office TV 2.x) is answered with
`{"ok":false,"msg":"This feature is not available on this TV app version."}`.

Status object:

```json
{"name":"Conference Room","model":"Dahua t982_ar301","android":"11","appVersion":"3.0","flavor":"full",
 "features":["cast","phone"],"accessibility":true,"needsPermission":false,"keepAwake":true,
 "webview":"120.0.6099.230","webviewOk":true,"casting":false,"phone":true,"phonePort":47300,"phoneConnected":false}
```

| Field | Meaning |
|---|---|
| `name` | TV name (1–40 chars), set with **Rename TV** on the TV. Defaults to maker + model. |
| `features` | What this app version supports. `["cast"]` in 3.0, `["cast","phone"]` since 3.3. |
| `accessibility` | Full flavor: the Accessibility service is on. Always false in the lite flavor. |
| `needsPermission` | Android 10+ only: true when the TV cannot open the cast screen while another app is in front (neither Accessibility nor "Display over other apps" is allowed). The TV's home screen shows the one-time setup. |
| `keepAwake` | **Keep screen on** is enabled (default). |
| `webview` | Version of the web engine the cast screen uses ("" if unknown). |
| `webviewOk` | False when that engine is known to be missing or older than 72 (then `cast start` fails with an update message). |
| `casting` | A cast screen is open on the TV right now. |
| `phone` | 3.3+: the TV accepts Android phone mirroring on the local network (section 10). |
| `phonePort` | TCP port of the phone mirroring server (47300–47309), 0 if it is not running. |
| `phoneConnected` | A phone is connected right now. |

## 6. Relay usage

- Relay base URL: `https://ntfy.sh` (the TV keeps an optional override in prefs key `relay_url`; the
  website stores one per TV; both default to ntfy.sh).
- **TV subscribe:** `GET <relay>/<topic>/json` (add `?since=<last message id>` after a reconnect so
  nothing is missed). The response is a never-ending stream of JSON lines:
  `{"id","time","event":"open|keepalive|message","topic","message",...}`. Only `event=="message"`
  lines are handled. Read timeout 90 s (ntfy sends a keepalive about every 45 s). Reconnect with
  back-off 1, 2, 4, 8, 16, 30, 60 s (reset after a successful `open`); after HTTP 429 wait at least 60 s,
  growing. The TV trusts the system CAs plus bundled ISRG roots (`assets/certs/`), so Android 5–7 TVs
  can reach Let's Encrypt sites.
- **Publish** (both sides): `POST <relay>/<topic>?firebase=no` with the envelope as a `text/plain` body.
  The TV adds `&cache=no` to acks. The browser sends it as a CORS "simple request" (no custom headers).
- **Website subscribe:** `EventSource("<relay>/<topic>/sse")`.
- The free ntfy.sh tier limits messages per public IP per day, and the whole office shares one IP.
  So nothing polls automatically: the website pings when a TV is selected, and a sharing session costs
  about 4 messages (§8). HTTP 429 should be shown to the user as a clear "limit reached, try again later".

## 7. Pairing link (optional)

`https://nikhildiwakar-bit.github.io/Portfolio/tv/#pair=<code>&name=<urlencoded TV name>`
(plus `&relay=<url>` if not the default). The code is in the URL fragment, so it is never sent to
GitHub's servers. The TV app no longer shows this link or a QR code: people type the code shown on the TV.

## 8. Share my screen (`cast`)

Media flows directly between the laptop browser and the TV (peer to peer, ICE server
`stun:stun.l.google.com:19302`, no TURN, so it works best when the laptop and the TV are on the same office
network); the relay only carries a few encrypted signaling messages. Code: `tv/cast.js` (both sides),
`tv/receive.html` + `tv/receive.js` (receiver page), `CastActivity.java` + `Commands.java` (TV).

1. **Laptop:** the click that connects to the TV (entering the code, or the "Share my screen" button for a
   saved TV) calls `getDisplayMedia(...)`, so the browser's own screen picker opens right away. It then
   opens a second event stream on the topic, creates the `RTCPeerConnection`, adds the tracks and a data
   channel `otv`, creates the offer and **waits for ICE gathering to complete** (max 4 s), so one offer
   carries every candidate (no trickle ICE).
2. Laptop → TV command `{"cmd":"cast","args":{"action":"start","session":<random 16 chars>}}`.
3. **TV app** opens `CastActivity` and loads
   `https://nikhildiwakar-bit.github.io/Portfolio/tv/receive.html#s=<session>&code=<TV code>[&relay=<url>]`
   (`relay` only when not the default; its value is URI-encoded). The URL is fixed in the app (the laptop
   cannot choose it). The fragment is never sent to a server; the page removes it from the address bar at
   once, and the WebView blocks all navigation, so the TV code never reaches another site. The only
   JavaScript interface is `OfficeTvCast.close()`. The ack:
   - `ok:true` "The TV is ready to show your screen." once the cast screen is open (the TV waits up to 8 s
     for it; `data` = status object).
   - `ok:false` "The TV needs a one-time setup before it can show your screen: on the TV, open Office TV
     and follow “Allow Office TV to open automatically”." when Android 10+ refused to open the screen
     from the background (§5 `needsPermission`).
   - `ok:false` "This TV's web engine is too old for screen sharing (version N, needs 72 or newer). Please
     update “Android System WebView” (or Google Chrome) from the TV's app store." (the TV shows the same
     message full screen for a few seconds).
   - `ok:false` "Invalid screen sharing session. Please reload the page and try again." for a bad session.
4. Laptop publishes the **offer** as `c2r` signal messages. The receiver subscribes with
   `/sse?since=5m`, so an offer published before the page finished loading is replayed by ntfy.
5. Receiver answers (again after ICE gathering completes) with `r2c` signal messages and plays the
   stream full screen (`object-fit: contain`, black background, sound on; if autoplay with sound is
   refused it plays muted and unmutes on the first remote key press).
6. **Stop:** the laptop sends `bye` over the data channel (no relay message) when the user presses
   "Stop sharing" or ends sharing in the browser's own bar. If the data channel is not open yet, it
   sends `{"cmd":"cast","args":{"action":"stop","session":…}}` instead (ack `ok:true`, "Screen sharing
   stopped on the TV." or "Screen sharing was not running on the TV."; a stop for any other session leaves
   the current one alone; an empty session stops whatever is shown). The receiver also ends when the
   peer connection fails, closes, or stays disconnected, and when no offer arrives in 90 s. It then calls
   `OfficeTvCast.close()`.

**The TV's cast screen** (`CastActivity`):

- One at a time (`singleTask`). A new `start` replaces the current session in place (the old WebView is
  destroyed, which closes its peer connection, so the old laptop sees the TV leave).
- Full screen (immersive), black, screen kept on, hardware accelerated; the screen is woken from standby.
  A native "Getting ready…" is shown until the receiver page has drawn; the page then shows its own
  "Waiting for the laptop…".
- **Back** on the remote (or Esc), the laptop's stop, `OfficeTvCast.close()` or a problem message timing out
  end the cast and show Office TV's home screen. Pressing Home, or another app covering the cast for 3 s,
  ends it too (without bringing Office TV back).
- WebView: JavaScript and DOM storage on, media autoplay without a gesture, no file or content access,
  no zoom, no pop-up windows, mixed content blocked, camera/microphone requests denied, Safe Browsing at
  its default. A renderer crash (Android 8+) closes the cast screen with a message instead of crashing the
  app. Load errors, HTTP errors, TLS errors (wrong TV clock) and a 45 s load timeout show a short,
  actionable message, then the home screen.

Signal message (plaintext, sealed exactly like commands: same key, AAD = topic, envelope < 3,900 bytes):

```json
{"v":1,"dir":"c2r","id":"…","ts":1760000000000,"session":"k3j9x0a2m1p4q8r2",
 "cast":"offer","part":0,"parts":1,"data":"z…"}
```

- `dir`: `c2r` (laptop → receiver) or `r2c` (receiver → laptop). The TV app (`c2t` only) and
  TvLink (`t2c` only) ignore these directions.
- `cast`: `offer` | `answer` | `bye`. `data` for offer/answer is the session description
  `{"type","sdp"}` as `"z" + base64url(deflate-raw(JSON))` (CompressionStream), or `"j" + JSON` when the
  browser cannot compress. Split into `parts` of at most 2,400 characters (max 8 parts); a typical
  compressed offer with all candidates fits in one message.
- The receiving side accepts only its opposite direction, its own `session`, `|ts/1000 − event.time| ≤ 300`,
  and each `id` once.

Relay cost of one sharing session: 4 messages (command, ack, offer, answer), plus 2 if stopped before
the connection was up.

  `phone=connected|config|screen opened|decoding …|disconnected …|rejected reason=auth|busy` (TV role) and

- A JSON API on **127.0.0.1 only** (port 8080–8090; reach it with `adb forward`), header `X-Token: <t>`:
  `GET /api/status` (status object + `code`, `relay`, `relayDetail`, `castSession`,

mirrors the emulator to itself over 127.0.0.1 (the app is sender and receiver at once).

## 10. Phone mirroring (3.3+, local network, no relay)

The same APK is the receiver on a TV and the sender on an Android phone (`Device.isPhone`: touchscreen,
not a TV, smallest width below 600 dp; debug builds default to TV). Source: `app/src/main/java/.../mirror/
MirrorProtocol.java` (pure Java, shared by both roles and by `tests/jvm/mirror/MirrorProtocolTest.java`).

**QR code** on the TV home screen:
`https://nikhildiwakar-bit.github.io/Portfolio/tv/phone.html#h=<TV IPv4>&p=<port>&k=<secret>&n=<TV name>`.
`k` is the TV's random 32-byte phone secret, base64url without padding (43 chars); it is replaced together
with the TV code (**New TV code**), which also ends a running phone session. The phone app handles that https
link and `officetvphone://connect?h=…&p=…&k=…&n=…` (the website's fallback deep link) in `PhoneSendActivity`.

**Transport:** one TCP connection from the phone to the TV, port 47300 (47301–47309 if taken), TCP_NODELAY.

**Handshake:**

| Direction | Bytes |
|---|---|
| phone → TV | `"OTVP1"` · nonce (16 random bytes) · HMAC-SHA256(secret, nonce ‖ `"phone"`) — 53 bytes |
| TV → phone (accepted) | `"OK"` · HMAC-SHA256(secret, nonce ‖ `"tv"`) — 34 bytes, proves it is the TV from the QR code |
| TV → phone (refused) | `"NO"` · reason: 1 = wrong secret (old QR code), 2 = busy (another phone is connected), 3 = version |

The TV closes the connection at once on wrong magic, compares MACs in constant time, allows 4 s for the
handshake and at most 4 handshakes at a time, and accepts one phone at a time.

**Messages** (both directions): `type u8 · length u32 big-endian · payload` (payload ≤ 8 MB).

| Type | Name | Direction | Payload |
|---|---|---|---|
| 1 | CONFIG | phone → TV | width u32 · height u32 · rotation u8 (0–3) · flags u8 · SPS length u32 · SPS · PPS length u32 · PPS (Annex-B, with start codes). Sent before the first frame and again after every encoder restart (rotation, resolution). |
| 2 | FRAME | phone → TV | flags u8 (1 = key frame) · pts i64 (µs) · one H.264 Annex-B access unit |
| 3 | PING | both | empty. The TV sends one every 2 s; the phone when it has sent nothing for 1.5 s. Either side gives up after 12–15 s of silence. |
| 4 | BYE | both | empty, or kind u8 (0 = normal end, 1 = error) · reason (UTF-8) shown on the other side |
| 5 | KEYREQ | TV → phone | empty: send a key frame now (decoder (re)started, or frames were dropped) |

**Latency rules.** Phone: hardware H.264 encoder with Surface input, long side ≤ 1920 (aspect kept, even or
16-aligned sides as the codec requires), ~8 Mbit/s (scaled down for smaller sizes), 60 fps (30 on weak devices),
key frame every 2 s, repeat the previous frame after 100 ms of a still screen, CBR if supported, `latency`
1 (API 30+), `priority` 0 (API 23+), SPS/PPS before every IDR (API 29+). A sender thread keeps at most 3
frames waiting; beyond that it drops non-key frames and requests a sync frame. TV: MediaCodec decoder on a
SurfaceView with `low-latency` 1 (API 30+), `priority` 0 and `operating-rate` 120 (API 23+) and common vendor
low-latency keys; each frame is queued on arrival and rendered as soon as it is decoded (no pts pacing); more
than 6 frames waiting are dropped up to the next key frame (and KEYREQ is sent).
