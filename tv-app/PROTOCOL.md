# Office TV remote protocol (v1)

This protocol lets a laptop, Chromebook or phone control a TV **without knowing the TV's IP address**.
Both sides talk through a public pub/sub relay, [ntfy.sh](https://ntfy.sh), and every message is
end-to-end encrypted, so the relay only sees random-looking text.

```
Controller page (https://nikhildiwakar-bit.github.io/Portfolio/tv/)
        │  POST encrypted command            ▲  SSE: encrypted ack
        ▼                                    │
     https://ntfy.sh/<topic>  ───────────────┘
        │  streaming GET /json
        ▼
   Office TV app (on the TV)  ── runs the command with Actions.java ──> posts encrypted ack
```

The LAN web page (`http://<tv-ip>:<port>/`) and its `/api/*` endpoints still exist and are unchanged.

Canonical test vectors: `tests/vectors.json` (generated by `tests/make-vectors.mjs`).
Both implementations **must** reproduce them exactly.

## 1. Pairing code

- 10 symbols from the Crockford base32 alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ` (50 bits).
- Generated once on the TV with `SecureRandom`, stored in prefs key `pair_code`. "Naya code banao"
  generates a new one; every controller paired with the old code stops working.
- Displayed as two groups of five: `7K3M9-QX2TD`.
- **Normalisation** of user input (controller side, and TV side when reading prefs):
  uppercase → remove spaces and `-` → map `O`→`0`, `I`→`1`, `L`→`1` → must then be exactly
  10 characters from the alphabet, otherwise invalid (`null`). `U` is invalid.

## 2. Derivation

All strings are UTF-8. `SHA256` is plain SHA-256.

| Value | Formula |
|---|---|
| topic | `"otv" + hex_lower(SHA256("officetv/topic/v1:" + code)[0..16))` → 35 chars |
| key | `SHA256("officetv/key/v1:" + code)` → 32-byte AES-256-GCM key |

## 3. Message envelope (ntfy message body)

```
otv1.<base64url(iv)>.<base64url(ciphertext || tag)>
```

- base64url **without padding** (RFC 4648 §5). Decoders must accept input with or without `=`.
- AES-256-GCM, 12-byte random IV, 128-bit tag, **AAD = UTF-8 bytes of the topic**.
- Plaintext is a UTF-8 JSON object (below). Any message that does not start with `otv1.`, or that
  fails to decrypt, is silently ignored. That is also how commands are authenticated: only someone
  who knows the pairing code can produce a valid envelope.
- Keep the whole envelope under **3,900 bytes**. ntfy turns bigger messages into attachments.

## 4. Plaintext JSON

Controller → TV (`dir: "c2t"`):

```json
{"v":1,"dir":"c2t","id":"k3j9x0a2m1","ts":1760000000000,"cmd":"open","args":{"url":"https://…"}}
```

TV → controller (`dir: "t2c"`):

```json
{"v":1,"dir":"t2c","id":"p0q8…","re":"k3j9x0a2m1","ts":1760000000950,
 "ok":true,"msg":"Link TV par khul gaya.","data":{},"part":0,"parts":1}
```

- `id`: 10+ random base36 chars, unique per message. `ts`: sender clock, milliseconds since epoch.
- Each side ignores messages with its own direction (both directions share one topic).
- **Freshness (TV side):** accept a `c2t` message only if `|ts/1000 − event.time| ≤ 300`, where
  `event.time` is the ntfy server's receive time in seconds (so the TV's own clock doesn't matter).
  If `event.time` is missing, compare with the TV clock. Also drop any `id` seen in the last 256
  messages. The controller's clock must be roughly right; laptops sync automatically.
- The controller matches acks by `re` against the commands it sent and ignores everything else.

## 5. Commands

Every command gets exactly one ack (or several `part`s for `apps`) with `ok` and a human `msg`
in Hinglish, the same text the LAN API returns.

| `cmd` | `args` | ack `data` |
|---|---|---|
| `ping` | `{}` | status object (below) |
| `open` | `{url}` | – |
| `youtube` | `{q}` | – |
| `key` | `{key}`: `back home recents next_slide prev_slide scroll_down scroll_up play_pause next previous volume_up volume_down mute wake` | – |
| `volume` | `{percent}` 0–100 | – |
| `awake` | `{on}` boolean | – |
| `apps` | `{}` | `{apps:[{label,pkg}]}`, split over `part`/`parts` so each envelope stays < 3,900 bytes |
| `app` | `{pkg}` | – |
| `file` | `{url, name, iv, size}` | – |
| `rename` | `{name}` (1–40 chars) | status object |

Status object:

```json
{"name":"Conference Dahua","model":"Dahua LPH65-ST420","android":"11","appVersion":"1.2",
 "flavor":"full","accessibility":true,"needsPermission":false,"keepAwake":true,
 "volume":6,"maxVolume":15,"lanUrls":["http://192.168.1.50:8080"]}
```

### Files (`file`)

1. The controller encrypts the raw file bytes with the same key, a fresh 12-byte IV and
   **AAD = UTF-8 of `topic + ":file"`**.
2. It uploads the ciphertext as an ntfy attachment:
   `POST https://ntfy.sh/<topic>?filename=otv.bin&firebase=no` with the bytes as the body.
   The response JSON has `attachment.url`.
3. It sends `{"cmd":"file","args":{"url":<attachment.url>,"name":"Sales.pptx","iv":<base64url iv>,"size":<plaintext bytes>}}`.
4. The TV downloads the URL (max 16 MiB, `https` only, host must be the relay host), decrypts it,
   saves it in the uploads folder under a sanitised name and opens it like a LAN upload.

ntfy.sh keeps attachments for a few hours and limits them to about 15 MB. The controller refuses
bigger files and suggests a Google Drive link or the same-Wi-Fi LAN page instead.

## 6. Relay usage

- Relay base URL: `https://ntfy.sh` (the TV keeps an override in prefs key `relay_url`, and the
  controller stores one per TV; both default to ntfy.sh).
- **TV subscribe:** `GET <relay>/<topic>/json` (add `?since=<last message id>` after a reconnect so
  nothing is missed). The response is a never-ending stream of JSON lines:
  `{"id","time","event":"open|keepalive|message","topic","message",...}`. Only `event=="message"`
  lines are handled. Read timeout 90 s (ntfy sends a keepalive about every 45 s). Reconnect with
  back-off 1, 2, 4, 8, 16, 30, 60 s (reset after a successful `open`).
- **Publish** (both sides): `POST <relay>/<topic>?firebase=no` with the envelope as a `text/plain` body.
  The TV adds `&cache=no` to acks. The browser sends it as a CORS "simple request" (no custom headers).
- **Controller subscribe:** `EventSource("<relay>/<topic>/sse")`.
- The free ntfy.sh tier limits messages per public IP per day, and the whole office shares one IP.
  So nothing polls automatically: the controller pings once when a TV is selected, and again only
  when the user presses refresh. HTTP 429 is shown to the user as a clear "limit reached" message.

## 7. Pairing link / QR

`https://nikhildiwakar-bit.github.io/Portfolio/tv/#pair=<code>&name=<urlencoded TV name>`
(plus `&relay=<url>` if not the default). The code is in the URL fragment, so it is never sent to
GitHub's servers. The controller saves `{name, code, relay}` in `localStorage` key `officetv.tvs`
and removes the fragment from the address bar.
